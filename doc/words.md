# STOIC.EXE word list

Every word in the shipped `STOIC.EXE`, grouped by branch. The list was generated by `tools/word-index --md > doc/words.md` from the kernel `header` macros (`saostoic-text/kernel/*.mar`) and the definitions in the STOIC files loaded by `stoic.cre` (rdef, image, float, obuf, vt100). It was then cross-checked against the INVENTORY output in `doc/data/stoic-inventory.txt`. To regenerate it, run the same command.

- **Word** is the name as it is looked up.
- **Kind** is how the word was made:
  - `code` is a kernel `header`.
  - `colon` is a `:` definition.
  - `immediate` is either of those with the IMMEDIATE attribute.
  - `AC xx` is an assembler word that compiles the byte `xx`.
  - Otherwise it is the defining word (`constant`, `variable`...) or the kernel macro (`system service`, `user variable`, `dispatch entry`).
- **Stack effect** quotes the source comment in STOIC's notation, `inputs, NAME, outputs`, top of stack last.
  - † marks an effect that is derived from the defining word or macro, not from a comment. `(F: ...)` is the float stack.
  - "(from file:line)" marks an effect carried over from an earlier definition of the same word.
  - "—" means the source gives none and the code was not read for one.
- **Source** is the final definition. Earlier ones follow "also".
- **Test** is the test file under `tests/` that uses the word most, or "—" if none does. It shows that the word is used, not that its stack effect was checked.

991 definitions were parsed, giving 950 distinct (branch, name) words. 964 of the definitions are on the global chain, and INVENTORY lists 964 entries, of which 964 match the source definitions in order. See [Mismatches](#mismatches-with-inventory) for the rest.

The base branch is the one the kernel starts in (`B_KERNEL`, `rkernel.mar:383-386`). It has no name: `STOIC<` pushes a separate branch, which nothing loaded into STOIC.EXE defines into.
